# スクロールテリング型イマーシブサイト リサーチ

> 出典: Awwwards SOTD / Codrops Case Studies / 業界分析記事  
> 調査日: 2026年7月

---

## 2026年のAwwwardsで起きていること

| 指標 | 数値 |
|---|---|
| SOTD受賞作のうちイマーシブ3D（2026 Q1） | **61%**（2024年は23%） |
| スクロール駆動型が静的3Dショーケースを上回る平均スコア差 | **+1.8pt** |
| 動画背景を使う受賞作の割合 | **< 8%**（2022年は40%超） |

審査の重心が「レイアウトの美しさ」から **「インタラクションの物語性」** へ移った。動画背景やヒーロー画像+テキストは差別化力を失い、スクロール位置を入力装置として物語を進める構成が標準になっている。一方でKalsoのようにWebGLなしでも世界観と物語性で受賞できることは変わらない。鍵は技術ではなく **「章立て」「ペーシング」「抑制」** という編集の規律。

> **コーポレートサイトにとっての示唆**  
> SaaS・テック企業のイマーシブ参入率は5%未満で、コーポレート領域は最も差別化余地が大きい。RazorpayはB2Bでも成立することを示している。Awwwardsのトレンドは18〜24ヶ月で一般案件の標準になる。

## ベンチマークすべき受賞事例

### 1. Cartier Watches & Wonders 2026
- **賞:** SOTD 2026/5 · 7.53
- **制作:** Immersive Garden
- **URL:** https://www.awwwards.com/sites/cartier-watches-wonders-2026
- **概要:** スクロールで複数の「世界（ユニバース）」を旅する構成。アイコニックな時計を1本ずつ、洗練された空間演出の中で見せていく。
- **学び:** 商品カタログを「章立ての旅」に変換する好例。1商品=1世界の割り切りが情報設計として明快。
- **タグ:** `ラグジュアリー` `章立て` `WebGL`

## 受賞作に共通する演出パターン

| パターン | 実装アプローチ | メモ |
|---|---|---|
| **章立て（チャプター）構成** | サイト全体を0→1の正規化スクロール進捗で管理し、進捗のしきい値ごとにカメラキーフレーム・マテリアル変化・テキスト出現をマッピング | 受賞サイトの共通アーキテクチャ。映画の絵コンテのように先にストーリーボードを描いてから実装する |
| **ピン留め＋スクラブ** | ScrollTriggerのpinでセクションを固定し、スクロール量をアニメーション進捗に変換（scrub）。ユーザーが「再生ヘッド」を握る感覚 | スクロールテリングの基本単位。テキストは固定し背景だけ変化させる型が読みやすい |
| **カメラスプライン演出** | 3D空間内にカメラの通り道（スプラインパス）を定義し、スクロールでカメラを進める。シーン間の移動が映画のワンカットに | 2026年受賞作の勝ちパターン筆頭。GSAPで補間するためユーザーが乱暴にスクロールしても滑らかに動く |
| **スナップスクロール** | GSAP Observerで入力（ホイール/タッチ/トラックパッド）を統一し、各シーンの静止点にスナップ | しきい値・速度・イージングの調整が体験の質を決める |
| **適応的ペーシング** | スクロール速度を検知し、速いときは省略版トランジション、ゆっくりのときはディテールや隠し要素を表示 | 審査員のクリエイティビティ評価と最も相関が強い演出 |
| **シームレスなページ遷移** | グリッド内のサムネイルをFLIP技法でヒーローへ拡大しながら裏でルートを切り替える | PodiumはGSAP Flipで実装。Next.jsのルーティングと両立できる |
| **音の空間演出** | 自動再生は絶対にせずユーザー操作でON。サブページでBGMにローパスフィルタ（「隣の部屋から聞こえる」感覚） | ページを「場所」として感じさせる仕上げ |

## 標準の技術スタック

受賞作・ケーススタディで驚くほど一貫している構成。自社スタック（Next.js + TypeScript + Zustand + GSAP）と8割重複しており、追加コストは Lenis + R3F のみ。

| レイヤー | ツール | 役割 |
|---|---|---|
| スムーススクロール | **Lenis** | 慣性スクロールの統一。GSAP tickerと同期させ、スクロールとアニメーションのリズムを一致させる |
| スクロール連動 | **GSAP ScrollTrigger** | ピン留め・スクラブ・進捗しきい値のマスタータイムライン制御。事実上の業界標準 |
| 入力統一・スナップ | **GSAP Observer** | マウス/タッチ/トラックパッドを単一イベントに統一。シーン単位のスナップ制御 |
| タイポグラフィ演出 | **GSAP SplitText** | 文字・行単位の分割アニメーション（2024年から無料化） |
| 3D描画 | **Three.js / React Three Fiber** | WebGLシーン。ヒーローシェーダー、3Dオブジェクト、カメラパス。R3FならReactコンポーネントとして管理 |
| 状態管理 | **Zustand** | ポインタ位置・スクロール進捗・遷移フェーズ・シーン状態をUIとWebGLの間で共有 |
| フレームワーク | **Next.js** | ルーティング・メタデータ・SSRコンテンツの土台。演出レイヤーはクライアント側に分離 |
| 軽量な代替 | **CSS view-timeline** | 単純なスクロール連動ならJS不要で実装できる新API。サブページの軽い演出向き |

## パフォーマンスと品質の基準

| 項目 | 基準 |
|---|---|
| **デバイス階層の検知** | 初回ロード前にGPU性能を判定し、低スペック端末にはパーティクル削減・シェーダー簡略版を配信。WebGL非対応には静的フォールバック |
| **アセット圧縮** | テクスチャはKTX2/Basis Universal（GPU直行デコード）、3DモデルはDraco圧縮glTF |
| **描画の規律** | 繰り返しジオメトリはGPUインスタンシングで1ドローコール。devicePixelRatioは1.5上限。AdaptiveDprでフレーム落ち時に解像度を動的に下げる |
| **重い処理の前倒し** | ジオメトリ生成・シャドウベイクはロード時に完了。スクロール中はuniform更新のみ（1フレーム4ms以内が目安） |
| **アクセシビリティ** | `prefers-reduced-motion` 対応は必須。音は必ずユーザー操作で開始 |

## 自社サイトへの適用案（3フェーズ）

### Phase 1 — 非WebGLで土台を作る（Kalso / Podium型）
- Lenis + ScrollTrigger導入。全ページのスクロールに統一された慣性を持たせる
- トップページを「会社の物語」の章立てに再構成（課題提起 → 私たちの答え → 事業/実績 → チーム → CTA）
- 各章はピン留め＋テキストのSplitText出現、画像のパララックスで構成。タイポと余白主導の抑制されたトーン
- `prefers-reduced-motion` と静的フォールバックを最初から組み込む

### Phase 2 — シグネチャー演出を1つ入れる
- ヒーローにWebGLシェーダー1枚（R3F）。マウス追従の歪みやノイズなど「1つだけ」記憶に残る演出を厳選
- 実績グリッド → 詳細ページをGSAP Flipのシームレス遷移に
- スクロール進捗・遷移フェーズをZustandで一元管理する設計に移行

### Phase 3 — フル・イマーシブ（Cartier / Radian型）
- 3D空間＋カメラスプラインで会社紹介を「ワンカットの旅」に
- 章単位のスナップスクロールと適応的ペーシング
- 物語の終点に必ずCV装置（問い合わせ・資料請求）を配置し「感動→行動」を閉じる
