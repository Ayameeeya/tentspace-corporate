# Blog style guide

> 憲法層。以下は HIRO が埋め、変更のマージは必ず人間が行う。

## 想定読者

- 主読者: AI エージェント・業務自動化の導入を検討している**発注側**（経営者・PM・技術責任者）
- 副読者: 同じ領域を実装する**実務者**（AI/Web エンジニア）
- 前提知識: プログラミングの基礎はあるが、記事の題材そのものは初見でも追える書き方をする（専門語の初出に一言の補足）

## トーンと一人称

- です・ます基調のラフ（短文・時々体言止め。「同僚に話すときの丁寧さ」）。既存記事群の文体に合わせる
- 経歴の自己言及（「20年やってきた」等）をしない。権威は判断と実装の中身に語らせる
- 売り込み・誘導の文言を本文に書かない（CTA はサイトテンプレートの標準導線に任せる）
- 断定は自分で検証した範囲のみ。未検証は「〜のはず」「未検証です」と正直に書く

## 構成の型

- 実装記録型（既定）: 背景と動機 → 構成（図 or 箇条書き）→ 実装の要点 → ハマりどころと対処 → まとめと次の一歩
- 速報解説型: 何が変わったか（一次情報リンク必須）→ 要点 3 つ以内 → 実務でどう使うか・使わないかの判断
- 導入検討型（発注者向け）: 課題 → 選択肢と比較 → 判断基準 → 導入時の注意
- いずれも見出しは 3 階層まで。1 記事 1 主題（複数主題は分割して内部リンク）

## NG 表現

- facts.md のネガティブリストに含まれる表現（唯一の禁止リスト。そちらを正とする）
- 誇張（「絶対」「最強」「完全に」「究極」）、根拠のない最上級、煽り（「〜しないと損」）
- 検証していない数値・ベンチマークの引用元なし記載
- AI が書いたことを隠す・偽る表現、および逆に不必要に AI 生成であることを強調する定型句

## 実在の人物・他社への言及ルール

- 他社の製品・サービス・ツールへの言及は、**公開情報（公式ドキュメント・公式発表・自分で検証した挙動）に基づく事実のみ**。伝聞・憶測・未確認のベンチマークを書かない
- 批判・欠点の指摘は**仕様と挙動の事実ベースに限定**する（「〜という制約がある」「〜の場合に失敗した」は可）。企業の姿勢・体質・人格への評価はしない
- 実在の人物への言及は、**公開の発言・発表・著作の引用のみ**。引用時は出典リンクを付ける。人物の意図・内心の推測を書かない
- 比較に自社（tent space）のサービスを含める場合、他社を不当に貶めて自社を優位に見せる構成にしない。自社の限界も同じ基準で書く
- 他社のロゴ・スクリーンショットは各社の利用ガイドラインに従う。スクリーンショットには撮影時点を明記する
- 障害・不具合に触れる場合は、復旧済みなら復旧の事実まで書く（古い障害情報だけを残さない）

## CTA 語彙

優先順位と最終定義は HIRO が確定する。

1. `inquiry`: 案件問い合わせ。指定がない場合の既定値
2. `app-download`: アプリのダウンロード
3. `camp-reservation`: キャンプ場の予約
4. `note-paid`: 有料 note への導線
