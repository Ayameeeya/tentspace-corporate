# 記事執筆ガイド

> 憲法層。本ガイドは、人間・AI を問わずすべての書き手が参照する記事記法の正本です。

## 利用可能な MDX コンポーネント

記事側で import は不要です。以下のコンポーネントは、すべての記事へグローバルに提供されます。

### LinkCard

一次情報や関連する記事を、タイトル・説明・画像・リンク先ドメイン付きの横長カードで示します。

内部記事は `slug` で指定します。タイトル、説明、カバー画像はコンテンツコレクションからビルド時に解決されます。存在しない slug や下書き記事を指定すると検証に失敗します。

```mdx
<LinkCard slug="claude-code-custom-skills-guide" />
```

外部ページは完全な `https://` URL を指定します。OGP と favicon はビルド時に取得され、キャッシュされます。取得できない場合は通常のテキストリンクとして表示され、記事のビルドは継続します。

```mdx
<LinkCard url="https://blog.cloudflare.com/example/" />
```

`slug` と `url` はどちらか一方だけを、文字列として指定してください。

## LinkCard の使い所

- 一次情報の主要リンクと、読者の次の理解につながる内部記事は、本文中のベタ貼りより LinkCard を推奨します。
- 目安は 1 記事につき 1〜4 枚です。
- 本文中の軽い言及や、文章の流れの中で読む短い参照はテキストリンクのままで構いません。
- カードだけを連続して羅列せず、それぞれのリンクを置く理由が分かる本文を添えます。

### Dialogue

記事が生まれた実際の会話を、話者ごとの吹き出しで再構成する導入コンポーネントです。記事側の import は不要です。

```mdx
<Dialogue>
  <Say by="hiro">別スレッドで話した内容を記事化したいときは、どうするのが楽ですかね</Say>
  <Say by="ai">一番楽な形は「話したスレッドの最後で一言」です。仕組みを作りましょう</Say>
</Dialogue>
```

利用できる話者は次の2名です。未定義の `by` はビルド時に検出されます。

- `hiro`: Hiro。右側・オレンジ系
- `ai`: AI。左側・グレー系

通常と異なる感情を伝える必要がある発言だけ、`mood` を指定できます。省略時は通常顔です。

```mdx
<Say by="hiro" mood="troubled">ちょっと困りましたね</Say>
<Say by="ai" mood="angry">それは見過ごせません</Say>
<Say by="hiro" mood="crying">これは悲しいです</Say>
```

利用できる表情は `normal` / `troubled` / `angry` / `crying` です。表情を装飾として多用せず、実在した会話の感情を補う場合だけ使います。

## Dialogue の使い所

- **記事冒頭の導入フック専用**です。本文の途中や結論には置かず、全編を対話形式にしません。導入で臨場感を作り、本文は地の文で書きます。
- 分量は **3〜6 往復**を目安にし、1発言は60字程度までの短い文にします。
- **実在した会話の再構成のみ**に使います。読みやすい言い回しへの整形はできますが、存在しなかった発言を創作してはいけません。
- 対話の素材は、仮説ページの発注書にある「冒頭対話案」を正とします。

## 運用ルール

本ガイドは、人間・AI を問わず全書き手の正本です。**MDX コンポーネントを追加したら、必ず本ガイドに記法と使い所を追記します。** このリポジトリを読むエージェントは、個別のプロンプトへ記法を書き写さず、本ガイドを参照してください。

既存記事への遡及適用は不要です。リライトや情報更新の機会に、自然な範囲で LinkCard や Dialogue を適用します。
