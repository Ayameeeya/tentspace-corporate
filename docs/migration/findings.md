## Content layer decision

The repository keeps the direct `gray-matter` + Zod + `@mdx-js/mdx` pipeline
already shipped with the migration. It provides schema validation, typed
manifest generation, RSC-compatible precompiled HTML, and fails the build on
invalid content. Switching to another content framework would replace working
code without changing the contract.

## SEO, analytics, and delivery

- RSS remains at `/feed`.
- Agent discovery is available at `/llms.txt`; the generated manifest is
  public at `/content-manifest.json`, and every published article has a static
  Markdown representation at `/blog/<slug>/index.md`.
- `app/sitemap.ts` emits static pages, all article URLs, and category URLs.
- Canonical, Open Graph, Twitter card, BlogPosting JSON-LD, breadcrumb JSON-LD,
  and organization metadata are generated by the existing routes.
- Every migrated article has an existing Open Graph image.
- GA4 and Vercel Analytics remain mounted in `app/layout.tsx`.
- Vercel deploys pushes to `main` and PR previews through
  `.github/workflows/vercel.yml`; archive upload is enabled for the 4,501-file
  prebuilt output.

## Traceability and repository hygiene

Source-system IDs, credentials, endpoint inventories, and URL mapping artifacts
are intentionally not retained in this repository. This follows the explicit
repository-hygiene decision made after the one-time import. URL parity is
verified from the unchanged 94 slugs instead.

## Automated publication readiness

> 以下は MDX 移行 compliance PR 作成時点の履歴である。
> 現在の記事運用は `AGENTS.md` を正とする。content-only PR は critic と
> 必須 CI の成功後に作成者が自己マージする。

Automated publication is not enabled in this migration compliance PR. The
repository currently has no readable branch-protection rule, configured writer
bot identity, semantic critic credential, or Slack notification secret. Enabling
auto-merge without those prerequisites would create an unreviewed publication
path. A separate human-reviewed PR must add and test that governance layer after
the external prerequisites exist.
