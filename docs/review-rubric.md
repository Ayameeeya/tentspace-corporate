# Content review rubric

> 憲法層。content-critic が公開可否判定に使う唯一のルーブリック。
> このルーブリックが `RESULT: PASS`、必須 CI が成功し、差分が
> `content/posts/**` のみに閉じた記事 PR は作成者による自己マージを許可する。
> それ以外の変更のマージは必ず人間が行う。

## 判定規則

- 全項目を順に検査する。
- 1 件でも重大な違反、確認不能、判断不能があれば `FAIL`。
- 指摘には項目名、該当箇所の短い引用、理由を含める。
- 修正案は提案できるが、critic 自身はファイルを変更しない。

## 1. 自社情報と facts

- [ ] 自社サービスの料金・仕様・条件が `facts.md` に存在する。
- [ ] 記事の記述が `facts.md` と矛盾しない。
- [ ] `facts.md` が未記入の項目を推測・補完していない。

未掲載、矛盾、または facts が空欄のため確認できない場合は `FAIL`。

## 2. 事実と出典

- [ ] 外部の事実主張、数値、引用に出典リンクがある。
- [ ] 一次情報を利用できる場合は一次情報を優先している。
- [ ] 出典が主張を直接支持し、断定の強さが証拠を超えていない。

## 3. 人物・他社への言及

- [ ] `docs/style-guide.md` の言及ルールに従っている。
- [ ] 誹謗、根拠のない比較、誤認を招く関係性の表現がない。

style guide が未記入で判定できない場合は `FAIL`。

## 4. Frontmatter と実験属性

- [ ] title、description、date、slug、categories、tags、draft がスキーマ準拠。
- [ ] 新規記事の `experiment` に `hook`、`cta`、`targetKw`、
  `utmCampaign` がすべてある。
- [ ] `cta` は許可語彙、slug はディレクトリ名と一致する。
- [ ] 同じ記事ディレクトリに `social.md` がある。

## 5. 文体と編集品質

- [ ] 想定読者、トーン、一人称、構成、NG 表現が style guide 準拠。
- [ ] 同じ説明の不要な反復、意味の薄い水増しがない。
- [ ] 読者の検索意図と CTA が記事内容に整合する。

## 6. SEO と重複

- [ ] キーワードの不自然な反復や隠しテキストなど、スパム的 SEO がない。
- [ ] 公開済み記事の実質的な複製ではない。
- [ ] 見出し・description が本文の内容を正確に表す。

## 出力形式

```text
RESULT: PASS または FAIL
- [ルーブリック項目] 指摘内容（該当箇所を引用）
```
