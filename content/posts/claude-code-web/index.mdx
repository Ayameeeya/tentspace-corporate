Claude CodeのWeb版の使い方を整理します。先に結論です。Web版（claude.ai/code）は「ブラウザ版のClaude Code」というより、**タスクをクラウドの隔離環境へ投げて、成果をブランチとPRで受け取る実行面**です。ローカルCLIの置き換えとして見ると物足りず、手元の作業と並走させる面として見ると位置づけがはっきりします。そして使い方の本体は、チャット画面の操作ではなく「環境」の設計にあります。

対象読者は、ローカルのClaude Codeは触ったことがあってWeb版は未体験の人と、ターミナルを開けない場面でもエージェントにタスクを投げたい人です。仕様は公式ドキュメント（確認日2026-09-29）に沿って整理しています。CLI自体がはじめての方は、先に[Claude Code入門](/blog/claude-code-getting-started)からどうぞ。

## Web版とは——「ブラウザで動く」ではなく「クラウドで実行される」

Web版のClaude Codeは、claude.ai/codeから使えるクラウド実行のClaude Codeです。ブラウザはあくまで指示と確認のための画面で、コードを読み書きする本体は、Anthropicが管理するクラウド上の隔離されたコンテナの中で動きます（[公式ドキュメント](https://code.claude.com/docs/en/claude-code-on-the-web)）。

<LinkCard url="https://code.claude.com/docs/en/claude-code-on-the-web" title="Claude Code on the web（公式ドキュメント）" />

ローカルCLIとの違いは、実行場所だけではありません。構造ごと違います。

- **作業対象**: 手元のディレクトリではなく、GitHub連携で接続したリポジトリ。セッション開始時にクラウド環境へcloneされます
- **成果物の受け取り**: 手元のファイルが直接変わるのではなく、セッションが専用ブランチへコミットし、そこからPRを作る流れになります
- **並列性**: セッションはそれぞれ独立したコンテナなので、複数のタスクを同時に走らせても手元の作業ツリーを取り合いません

ローカルで並列実行しようとするとgit worktreeで作業ツリーを分ける工夫が要りますが（[worktree並列実行の記事](/blog/claude-code-git-worktree-parallel)で整理しました）、Web版は構造からしてセッション＝独立環境なので、その工夫が最初から要らない形です。

## 始め方——GitHub連携からタスク投入まで

セットアップの流れは4つです。インストールは不要で、ブラウザだけで完結します。

### 1. claude.ai/codeを開いてサインイン

Claudeのアカウントでサインインします。利用できるプランは変わることがあるので、契約前に公式の最新情報を確認してください。

### 2. GitHubアカウントを接続し、Claude GitHub Appをインストール

初回はGitHubアカウントの接続を求められます。あわせて、対象リポジトリにClaude GitHub Appをインストールします。組織のリポジトリの場合は、組織のオーナー権限での承認が必要になることがあります。ここで許可したリポジトリだけがWeb版から扱える対象になるので、「全リポジトリ」ではなく必要なものに絞って渡すのが安全側の選択です。

### 3. リポジトリと環境を選ぶ

セッションを始めるときに、対象リポジトリと実行環境を選びます。環境には、後述するネットワークポリシーや環境変数、セットアップ用のスクリプトといった設定が紐づきます。最初は既定の環境のままで始めて、詰まったところから設定を足していくので十分です。

### 4. タスクを書いて投げる

あとはローカルと同じで、自然言語でタスクを書くだけです。ここで効くコツもローカルと同じで、最初は「対象と期待結果が1文で言えるタスク」を選ぶこと。ただしWeb版はタスクを投げて結果を受け取る構造なので、指示の時点で完了条件まで書き切っておくほうが迷子になりにくいはずです。

```text
> READMEのセットアップ手順が現行のnpm scriptsと食い違っていないか確認して、
> ズレていたら修正してPRを作ってください
```

セッションは途中で追加の指示を送って軌道修正できますし、複数のセッションを並べて別々のタスクを進めることもできます。

## 実行環境の仕組み——セッションごとに使い捨てのコンテナ

Web版を使ううえで一番押さえておきたいのが、実行環境のライフサイクルです。

セッションが始まると、隔離されたコンテナが用意され、そこへ対象リポジトリが新しくcloneされます。このコンテナは使い捨てで、セッションが終わるか一定時間操作がないと回収されます。つまり、**コミットしてpushしたものだけが残り、それ以外のコンテナ内の状態は消えます**。

この性質は、制約というより設計の前提として受け取るのがよいと思います。

- 残したい成果は必ずブランチへコミットさせ、pushまで確認する
- 「環境に何かを入れて次回も使う」という発想は捨て、環境構築は毎セッション再現可能な形（後述のセットアップスクリプト）に書き下す
- 逆に言えば、実験的な変更で環境を汚しても、次のセッションはまっさらな状態から始まります

ローカルの感覚で「さっき入れた依存がまだあるはず」と考えると、この揮発性が最初のつまずきどころになるはずです。

## つまずきの正体は画面ではなく「環境の設計」

使い方の説明としてはここまでで動きます。ただ、仕様を読み解いていくと、チャット画面の操作で迷う要素は多くないはずで、学習コストの本体はUIではなく次の2つの環境設計にあると見ています。

### ネットワークポリシー

クラウド環境からの外向き通信は、環境を作るときに選んだネットワークポリシーで制御されます。外部への接続を絞った設定では、テストやビルドが外部サービスへ届かずに失敗することがあります。これはWeb版の不具合ではなく、隔離が仕事をしている状態です。

エージェントに自由なネットワークを渡すことのリスクは、[サンドボックス入門の記事](/blog/claude-code-sandbox)で「壁とルールは別物」として整理しました。Web版のネットワークポリシーはその「壁」をAnthropic側の環境で提供してくれるものなので、既定の制限を安易に緩めるのではなく、必要な宛先を把握してから開けるのが筋です。

### セットアップスクリプトと環境変数

コンテナは毎回まっさらなので、依存のインストールやビルド準備は環境側の設定として持たせます。環境には環境変数とセットアップ用のスクリプトを設定でき、リポジトリ側ではSessionStartフックでセッション開始時の準備処理を定義できます。「テストが通る状態までを自動で作る」設定を一度書いておくと、以後のセッションはタスク本体からすぐ始められます。

ここを整えないままタスクを投げると、エージェントは毎回依存インストールの試行錯誤から始めることになり、時間もトークンも準備作業に食われます。**Web版の使い勝手は、チャットの書き方より環境定義の完成度で決まる**。これがWeb版を整理していて一番はっきりした点です。

## CLI・GitHub Actionsとの使い分け

同じClaude Codeでも、実行面は3つに分かれました。判断軸を並べます。

- **ローカルCLI**: 対話しながら詰める作業、ローカル環境（DB、実機、秘匿ファイル）に依存する作業。テンポの速い往復が要るならここ
- **Web版**: 完了条件を書き切れる独立したタスクを、手元の作業と並走させたいとき。外出先やターミナルを開けない場面からの投入も含みます
- **GitHub Actions連携**: IssueやPRのコメントを起点に、リポジトリのイベントへ反応させたいとき。トリガーが「人の思いつき」ではなく「リポジトリ上の出来事」ならこちらです

Web版とActions連携は「クラウドで動く」点が同じで迷いやすいですが、起点が違います。自分がタスクを思いついて投げるならWeb版、リポジトリ側の出来事に反応させるならActions連携。後者の設定と権限設計は[GitHub Actions連携入門](/blog/claude-code-github-actions)にまとめています。

## まとめ——最初のセッションまでの進め方

Web版の始め方を、進め方として並べ直します。

1. claude.ai/codeにサインインし、GitHub連携でClaude GitHub Appを必要なリポジトリだけにインストールする
2. 既定の環境で小さなタスクを1つ投げ、ブランチとPRで成果を受け取る流れを体験する
3. 詰まった箇所（依存・外部通信）を、セットアップスクリプトとネットワークポリシーの設定に書き下す
4. 完了条件を書き切れるタスクをWeb版へ、対話が要る作業はローカルCLIへ、と振り分けを固める

コンテナは使い捨て、成果はpushしたものだけ、使い勝手は環境定義で決まる。この3点を前提にすれば、Web版は「ローカルの劣化版」ではなく、並列に走る実行面として手元の開発に足せます。次の一歩としては、クラウドと同じ発想でローカル側の隔離を整える[サンドボックス設定ガイド](/blog/claude-code-sandbox-settings)、定時実行に組み込む[ヘッドレスモード](/blog/claude-code-headless-mode)あたりが続きになります。
