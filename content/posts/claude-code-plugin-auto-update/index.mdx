Claude Code 2.1.331（2026-11-23）の変更履歴に、日付付きの予告が入りました。2026年11月30日以降のリリースから、managed設定の `extraKnownMarketplaces` に登録したプラグインmarketplaceは**既定で自動更新される**ようになります。除外したいmarketplaceには、エントリへ `"autoUpdate": false` を明示する。つまり今後は「書かない＝追従する」です。

結論から言うと、ここで考えるべきは自動更新の是非そのものより、**自分の設定に「何も書いていないエントリ」が何個あるか**です。既定の変更は、設定を明示している人には効きません。暗黙に任せていた部分の挙動だけが、提供側のカレンダーで変わります。

想定読者は、チームや組織でmanaged設定を配っていてプラグインの供給を管理する立場の方と、Claude Codeを無人実行で回していて「版を上げたら挙動が変わった」を避けたい方です。何が予告されたか、業界の並行する動き、版を上げる前に数える3点の順で整理します。

## 何が予告されたか——「書かない」エントリが追従する側へ

[公式の変更履歴](https://code.claude.com/docs/en/changelog)の2.1.331（2026-11-23付）に入った予告は次の内容です。

- 2026年11月30日以降の将来リリースで、managed設定の `extraKnownMarketplaces` にあるプラグインmarketplaceが既定で自動更新される
- 個別に除外するには、該当エントリへ `"autoUpdate": false` を設定する

<LinkCard url="https://code.claude.com/docs/en/changelog" title="Claude Code 公式変更履歴" />

前提を補足します。Claude Codeのプラグインは、スラッシュコマンド・スキル・hooks・MCP設定を1つの箱にまとめて配る仕組みで、marketplaceはその配布棚です。組織の管理者は、managed設定（管理者が配布し、利用者側で上書きできない設定）の `extraKnownMarketplaces` で「この棚を使う」をメンバーへ届けられます。仕組みの全体は入門記事で書いたので、この記事は更新の統制に絞ります。

<LinkCard slug="claude-code-plugins" />

今回のポイントは、機能の新設ではなく**既定の反転**であることです。自動更新という選択肢自体は設定として存在し、今後は「する」側が既定になる。これまでどおり固定しておきたい棚があるなら、`"autoUpdate": false` を書く側に回ります。日付を切った予告型の変更なので、対応の期限も明確です。

なお2.1.331は、この予告以外にも統制の既定に関わる変更がまとまって入った版です。変更履歴から拾うと、PermissionDeniedフックの `retry: true` が伝える内容が「拒否された呼び出しの再実行は、自分がその呼び出しを求めた場合だけ」に変わり、プラグインmanifestには一緒に導入されつつ単体で無効化・アンインストールできる `optionalDependencies` が追加され、`allowManagedPermissionRulesOnly` 設定時のVS Codeの権限カードはallowルールを提示せずYes/Noだけを表示するようになりました。方向はそろっていて、**管理者が決めた線を、利用者の画面や既定が勝手に越えない**ようにする変更群です。

## 同じ週、GitHubはチーム既定のプラグイン配布をGAにした

並行する動きとして、GitHubは2026-11-18の変更履歴で、チームのmaintainerとorganization ownerが承認済みAgent Pluginを**チームの既定プラグイン**として設定できる機能をGAにしています。設定場所はチームのCustomize Copilotタブで、既定化したプラグインはチームの直接メンバーのVS Code・GitHub Copilotアプリ・Copilot CLIで既定有効になります。

<LinkCard url="https://github.blog/changelog/2026-11-18-customize-github-copilot-for-your-team" title="GitHub公式: Customize GitHub Copilot for your team" />

興味深いのは階層の設計です。子チームは親の既定を継承しない。メンバーはポリシーが許す範囲でオフにできる。そしてenterpriseとorganizationのポリシーがチームの選択を上書きし、必須・禁止プラグインとmarketplaceの許可はクライアント側で強制される。つまり「誰が既定を決め、誰がそれを外せるか」が仕様として明文化されています。

Claude Codeの自動更新既定化も、GitHubのチーム既定配布も、向きは同じです。エージェントの拡張は「個人が好きに入れるもの」から、**組織が既定を決め、個人は決められた範囲で外すもの**へ寄っています。そして既定を決める側に回った管理者は、導入の既定だけでなく、今回のような**更新タイミングの既定**にも答えを持つ必要が出てきました。

## 設定ファイルは昨日のまま、意味だけが版で変わる

この予告を読んで思い出したのは、1つ前の版の変更です。2.1.330では `deniedMcpServers` の名前指定の実効範囲が「同一URLの他コネクタも隠す」から「指定したコネクタだけを隠す」へ縮小されました。[名前指定では実行を止められない件](/blog/claude-code-denied-mcp-servers)として先日整理したとおり、設定ファイルを1文字も変えていなくても、版を上げると拒否の効く範囲が変わる。今回の自動更新既定化も同じ型で、**設定の意味は版が決める**という事実が連続して表に出ています。

この型の変更が厄介なのは、差分レビューに現れないことです。設定ファイルのgit履歴はきれいなまま、実効値だけが動く。私自身、2026年8月に「書いてある設定」と「実際に効いている先」のズレで失敗したことがあります。デプロイ設定の `wrangler.jsonc` が休眠中のリポジトリを指していて、本物のPRがそちらへマージされていた。コード自体は健全で、設定とドキュメントが揃って誤った参照先を示していたので、読んだだけでは気づけませんでした。この経験から、「設定に書いてある値」とは別に「いま実際に効いている値」を確かめる口を挟む価値がある、と考えています。

既定の変更は、このズレを外部要因で作ります。自分は何も変えていないのに、提供側のカレンダーが来ると実効値が変わる。だから予告が出た時点でやることは、議論ではなく棚卸しです。

## 版を上げる前に数える3点

対応は難しくありません。順番に数えるだけです。

**1. エントリの数と、autoUpdateの明示率。** managed設定の `extraKnownMarketplaces` に並ぶエントリを列挙し、全部に `autoUpdate` の値を明示します。追従させたい棚にも `true` を書く。目的は「falseを付けること」ではなく、**暗黙のエントリを0にすること**です。明示してあれば、次に既定が動いても自分の設定は影響を受けません。

**2. その設定がどこで効いているか。** managed設定は配布物なので、書いた場所と効く場所が離れています。2.1.331の変更履歴には、WindowsではHKLMのレジストリポリシーが `managed-settings.json` より優先し、不正な値では起動が止まりうることも明記されました。配布先の環境で実効値を確認する経路を1つ持っておくと、この種の変更のたびに推測で悩まずに済みます。

**3. 依存の切り離し線。** 同じ版で入った `optionalDependencies` は、プラグインと一緒に導入されつつ、単体で無効化・アンインストールできる依存です。自動更新で棚の中身が入れ替わっていく前提に立つなら、「問題が出たときにどの単位で止められるか」を先に把握しておく価値があります。

そのうえで、私の線引きはこうです。**人が毎日触る対話環境の棚は追従（true）でよい。無人実行が読む棚はfalseを明示する。** 対話環境なら挙動の変化にその場で気づけますが、無人のRoutineでは、変わったことに誰も気づかないまま実行だけが走ります。入門記事で「無人運用では更新経路を増やしたくない」と書いた判断の延長で、固定した棚の更新は、版上げと同じく人が見ている日にまとめて行う側に倒します。

## プラグインの統制は3つの質問に分かれた

整理すると、エージェント拡張の統制は3つの質問に分解されてきています。

- **入れるか**——配布の既定。Claude Codeの `extraKnownMarketplaces` と `enabledPlugins`、Copilotのチーム既定配布
- **固定するか**——バージョンやSHAの固定。固定が検証として機能していなかった脆弱性の教訓は以前書きました
- **追従するか**——更新の既定。今回の `autoUpdate` はここに初めて明示的な欄を作った

<LinkCard slug="claude-code-cve-2026-86063" />

3つは別の質問で、別の設定で答えます。「一覧から消す」と「実行を止める」を混同していた `deniedMcpServers` の件と同じで、統制は1つの欄に混ぜた瞬間に読み違いが始まります。

11月30日は、締切というより暗黙を数える口実です。エントリを列挙して、全部に向きを書く。それだけで、この予告は事故の種ではなくただの予定になります。
